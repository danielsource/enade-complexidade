\section{Fundamentos}
\begin{quote}
    \itshape
    ``If computers were infinitely fast and computer memory were free, would you have any reason to study algorithms?
    The answer is yes, if for no other reason than that you would still like to be certain
    that your solution method terminates and does so with the correct answer.'' \parencite[12]{clrs2022}\\[-6pt]
    \rule{\linewidth}{0.3pt}
\end{quote}

Analisar a eficiência é o foco central da disciplina de Complexidade de Algoritmos.
Essa subárea examina o custo de tempo, memória ou outros recursos necessários para resolver problemas computacionais;
e a complexidade é a métrica definida de forma abstrata (em vez de usar o tempo de execução ou outro recurso real)
para descrever a eficiência do algoritmo independentemente da sua implementação real \parencite[275--276]{sipser2012}.

Uma vez que temos um algoritmo implementado, é simples cronometrar o seu tempo de execução.
Porém, o algoritmo será mais rápido em um computador mais performático~---
que consegue executar mais instruções ou processar mais dados~---
em comparação a um computador menos performático.

Como bem pontuado em \textcite[27]{clrs2022} na análise do \textit{insertion sort},
para descobrir quanto tempo esse algoritmo de ordenação gasta, uma forma seria rodar em seu computador.
Mas para isso, seria necessário implementar o algoritmo numa linguagem de programação real.
O resultado desse teste te daria quanto tempo gastou aquela implementação, com uma certa entrada,
com algum compilador ou interpretador, usando bibliotecas específicas,
com tarefas diversas rodando em plano de fundo no seu sistema operacional.

Isso nos mostra que esse teste é possível, porém volátil.
Para podermos focar no algoritmo geral e não numa implementação em particular
(por exemplo, para decidir qual algoritmo utilizar dentre vários),
teremos que usar um método que independa desses detalhes, mas nos dê informação suficiente;
analisando a ideia, ou a descrição abstrata em pseudocódigo, por exemplo.

Dessa forma, utilizemos como base uma simplificação do modelo computacional de \textcite[26]{clrs2022},
assumindo uma máquina de acesso-aleatório (\textit{random-access machine})
com um único processador, sendo que esse executa instruções uma após a outra, sem operações concorrentes.
Nesse modelo, temos operações lógico-aritméticas (adição, subtração, multiplicação, divisão, operadores lógicos, etc.),
operações de movimento de dados (carregar, guardar, copiar dados)
e operações de controle (desvios condicionais e incondicionais, sub-rotinas).
Essas operações podem manipular inteiros, números de ponto flutuante e caracteres.

Para o propósito deste resumo de análise da complexidade de algoritmos,
começaremos enxergando que cada $k$-ésima linha de pseudocódigo tem o custo constante $c_k$.
E assim, o tempo de execução de um algoritmo será visto como a soma dos custos das linhas executadas.
Exemplificando com o pseudocódigo adaptado de \textcite[25]{clrs2022}:
\listtitle{Sum-Array(\texttt{A, n})}
\begin{Verbatim}[numbers=left, commandchars=\\\{\}]
sum = 0                 # custo = \(c\sb{1}\),    vezes = \(1\)
for i = 0 to n - 1      # custo = \(c\sb{2}\),    vezes = \(n + 1\)
    sum = sum + A[i]    # custo = \(c\sb{3}\),    vezes = \(n\)
return sum              # custo = \(c\sb{4}\),    vezes = \(1\)
\end{Verbatim}
O algoritmo \textit{Sum-Array} retorna a soma dos valores do vetor \texttt{A}.
Nesse algoritmo, temos que a linha 1 tem um custo $c_1$ e é executada $1$ vez,
já a linha 2 tem um custo $c_2$ e é executada $n + 1$ vezes, pois o intervalo do laço é fechado de $0$ até $n - 1$,
e é necessário fazer o teste da condição do laço quando $i = n$.
Iremos denotar o tempo de execução de um algoritmo com uma entrada de tamanho $n$ por $T(n)$,
obtendo isto para \textit{Sum-Array}:
\[
    T(n) = c_1 + c_2(n + 1) + c_3n + c_4.
\]

\subsection{Análise por casos}
O exemplo anterior com \textit{Sum-Array} mostra que o tempo de execução ($T(n)$) pode depender do tamanho da entrada ($n$).
Porém, existem algoritmos em que $T(n)$ também depende da própria configuração da entrada, por exemplo:
\listtitle{Linear-Search(\texttt{A, n, k})}
\begin{Verbatim}[numbers=left, commandchars=\\\{\}]
i = 0
while i < n and A[i] != k
    i = i + 1
if i == n
    return -1
return i
\end{Verbatim}
O algoritmo \textit{Linear-Search} retorna o índice do primeiro elemento do vetor \texttt{A} que seja igual a \texttt{k}, caso contrário, retorna \texttt{-1}.
Caso tenhamos que \texttt{A[0] == k}, o teste da condição do laço irá rodar uma vez e sair imediatamente, pois \texttt{A[i] != k} é falso.
Por outro lado, se \texttt{A} não contém \texttt{k}, o laço irá rodar $n$ vezes e retornar \texttt{-1}.
Portanto, existe a necessidade de analisar um mesmo algoritmo em diferentes casos.

Conforme \textcite[31]{clrs2022}, iremos nos concentrar em achar apenas o pior caso, isto é,
o maior $T(n)$ para qualquer entrada de tamanho $n$.
Ao encontrar esse pior caso, temos a garantia de que o algoritmo nunca vai demorar mais que isso.

\section{Questões}
\begin{question}{2014-12}
Analise o custo computacional dos algoritmos a seguir, que calculam o valor de um polinômio de grau $n$, da forma:
$P(x) = a_nx^n + a_{n-1}x^{n-1} + \dots + a_1 x + a_0$,
onde os coeficientes são números de ponto flutuante armazenados no vetor $a[0..n]$, e o valor de $n$ é maior que zero.
Todos os coeficientes podem assumir qualquer valor, exceto o coeficiente $a_n$, que é diferente de zero.

\medskip\noindent\begin{minipage}{\linewidth}
\listtitle{Algoritmo 1}
\begin{Verbatim}[numbers=left]
soma = a[0]
Repita para i = 1 até n
    Se a[i] != 0.0 então
        potência = x
        Repita para j = 2 até i
            potência = potência * x
        Fim repita
        soma = soma + a[i] * potência
    Fim se
Fim repita
Imprima(soma)
\end{Verbatim}

\listtitle{Algoritmo 2}
\begin{Verbatim}[numbers=left]
soma = a[n]
Repita para i = n-1 até 0 passo -1
    soma = soma * x + a[i]
Fim repita
Imprima(soma)
\end{Verbatim}
\medskip
\end{minipage}

\noindent
Com base nos algoritmos 1 e 2, avalie as asserções a seguir e a relação proposta entre elas.

\begin{enumerate}[label=\Roman*.]
    \item Os algoritmos possuem a mesma complexidade assintótica.
\end{enumerate}

\begin{center}
    \textbf{PORQUE}
\end{center}

\begin{enumerate}[label=\Roman*., start=2]
    \item Para o melhor caso, ambos os algoritmos possuem complexidade $O(n)$.
\end{enumerate}

\noindent
A respeito dessas asserções, assinale a opção correta.

\begin{spacing}{0.9}
\begin{small}
\begin{enumerate}[label=\Alph*)]
    \item As asserções I e II são proposições verdadeiras, e a II é uma justificativa correta da I.
    \item As asserções I e II são proposições verdadeiras, mas a II não é uma justificativa correta da I.
    \item A asserção I é uma proposição verdadeira, e a II é uma proposição falsa.
    \item A asserção I é uma proposição falsa, e a II é uma proposição verdadeira.
    \item As asserções I e II são proposições falsas.
\end{enumerate}
\end{small}
\end{spacing}

\begin{solution}
\textbf{Solução:} antes de falar de cada uma das asserções e alternativas, vamos descrever a ideia dos dois algoritmos:

\textbf{Algoritmo 1:} percorra o vetor fazendo um somatório de cada $i$-ésimo termo do polinômio;
para cada termo com coeficiente não nulo, percorra um laço interno $i - 1$ vezes para calcular a $i$-ésima potência de $x$,
incrementando nossa soma com $a_ix^i$.

Assim como visto em \textcite[34]{clrs2022} usando o algoritmo \textit{insertion sort},
o Algoritmo 1 também utiliza uma abordagem \emph{incremental}, pois para cada $i$-ésima iteração,
temos uma parte da solução do problema (no caso do \textit{insertion sort}, um subvetor ordenado $V[0..i-1]$),
realizando um trabalho adicional que cresce linearmente conforme o algoritmo avança.

Similar ao \textit{insertion sort}, esse algoritmo tem um custo de tempo no pior caso de $\Theta(n^2)$~---
quando todo coeficiente $a_i$ (com $1 \le i \le n - 1$) é diferente de zero e logo o bloco interno sempre é executado~---
e também tem o custo de tempo no melhor caso de $\Theta(n)$~---
quando todo coeficiente $a_i$ é igual a zero e logo o bloco interno é executado apenas na iteração $i = n$ \parencite[33]{clrs2022}.

\textbf{Algoritmo 2:} percorra o vetor de trás para frente fazendo um somatório de cada $i$-ésimo termo do polinômio,
incrementando nossa soma com o seu valor anterior multiplicado por $x$ e adicionando o coeficiente $a_i$.
Para visualizar melhor, entenda que \texttt{soma} tem seu valor alterado ao longo do tempo desta forma:
\[
    \begin{aligned}
    \text{soma} &\gets a_n &&\text{(valor inicial antes do laço)}\\
    \text{soma} &\gets (a_n)x + a_{n-1}, &&\text{ou }\quad a_nx + a_{n-1}\\
    \text{soma} &\gets (a_nx + a_{n-1})x + a_{n-2}, &&\text{ou }\quad a_nx^2 + a_{n-1}x + a_{n-2}\\
    \text{soma} &\gets (a_nx^2 + a_{n-1}x + a_{n-2})x + a_{n-3}, &&\text{ou }\quad a_nx^3 + a_{n-1}x^2 + a_{n-2}x + a_{n-3}\\
    &\vdots\\
    \text{soma} &\gets a_nx^n + a_{n-1} x^{n-1} + \dots + a_1 x + a_0 &&\text{(totalizando $n$ iterações)}.
    \end{aligned}
\]
De acordo com \textcite[879]{clrs2022}, esse algoritmo utiliza a regra de Horner para avaliar um polinômio em tempo $\Theta(n)$,
pois possui um laço e esse não contém nenhuma estrutura condicional ou outro laço interno.\\

Com essa ideia inicial, agora podemos modelar assintoticamente ambos os algoritmos.

\end{solution}
